## 摘要
长期记忆使LLM智能体能够进行持久个性化，但重复的基于记忆的条件响应可能会累积性地泄露受保护属性，即使这些属性从未被明确说明。我们将这种威胁形式化为自适应转录隐私，并引入DP-MemView，一个差分隐私接口，它私下选择公开的响应条件视图，并将这些视图（而非原始记忆）暴露给响应LLM。每次私有选择都会对每个其记忆组与读集相交的受保护属性收费。按属性分类的账本会阻止任何超过其配额的查询，并返回一个固定的通用视图。在明确的接口契约下，我们证明了整个自适应转录的纯B_a-DP。我们还将结果扩展到在多个受保护组之间不同的存储，并限制观察转录可以改变攻击者先验几率的程度。我们在受控的相邻存储基准和公共语料库迁移轨道上评估了在线和预分配模式与三个响应LLM。两种模式都将转录可区分性保持在接近随机的水平，同时保留目标所需的个性化和整体响应质量。进一步的诊断表明，移除关键保障措施会导致输出支持不匹配、缺失账本计费、揭示侧信道或增加长期泄漏。

## Abstract
Long-term memory enables persistent personalization in LLM agents, but repeated memory-conditioned responses can cumulatively reveal protected attributes even when they are never stated explicitly. We formalize this threat as adaptive transcript privacy and introduce DP-MemView, a differentially private interface that privately selects public response-conditioning views and exposes those views---rather than raw memory---to the response LLM. Each private selection is charged to every protected attribute whose memory group intersects the read set. Per-attribute ledgers block any selection that would exceed its cap and return a fixed generic view instead. Under an explicit interface contract, we prove pure B_a-DP for the entire adaptive transcript. We also extend the result to stores that differ across multiple protected groups and bound how much observing the transcript can change an adversary's prior odds. We evaluate the online and preallocated modes with three response LLMs on a controlled adjacent-store benchmark and a public-corpus transfer track. Both modes keep transcript distinguishability near chance while preserving target-required personalization and overall response quality. Further diagnostics show that removing key safeguards causes mismatched output support, missing ledger charges, revealing side channels, or growing long-horizon leakage.

## 1. 核心问题与整体含义

- **研究背景**：长期记忆使LLM智能体能够跨会话存储、检索和更新用户上下文，实现持久个性化。但这种持久性带来了新的隐私问题——敏感属性不一定要在单个回答中出现，而是可能从大量看似良性的、受记忆条件影响的响应中被逐步推断出来。
- **具体威胁场景**：外部半可信应用程序无法直接访问原始记忆，也不能直接查询受保护属性（如“用户是否有糖尿病”），但可以通过反复提交普通任务查询（如“建议三顿实惠晚餐”），观察智能体基于记忆生成的个性化响应，从而累计推断出受保护属性。
- **核心问题**：现有防御（如掩码敏感片段、保护RAG输出、任务级最小化）限制了直接暴露，但未能为跨多次记忆条件发布累计的隐私损失提供可组合的、先验无关的保证。
- **研究目标**：形式化“自适应转录隐私”威胁，并设计一个位于记忆接口处的差分隐私边界，使整个自适应交互序列满足纯DP保证，而非单次响应隐私。

## 2. 方法论

**核心思想**：将原始记忆与响应生成LLM隔离，在可信接口内部完成所有记忆依赖的评分和视图选择，仅向响应LLM暴露公有视图（而非原始记忆或内部分数）。

**关键技术细节**：

- **槽位级视图选择**：每个记忆位置归属于策略定义槽位（如健康、饮食、财务、工作）。每个槽位固定一个跨相邻存储共享的公有视图词汇表（含一个固定通用视图）。视图编码“如何回答”而非用户事实，如健康视图要求“血糖意识建议”而不断言诊断。
- **属性级计费（Attribute-Level Charging）**：每次读取触及哪些受保护属性由 `Γ⋆(Rt,g) = {a ∈ A : Rt,g ∩ Ia ≠ ∅}` 确定；声明计费集合必须覆盖所有受影响属性（允许过度计费，但不允许遗漏）。
- **指数机制（Exponential Mechanism）**：对每次被准入的私有选择，按式(7)采样视图，其中内部评分函数 `ut,g(qt, v; MRt,g) ∈ [0,1]`，灵敏度上界满足式(6)，局部隐私预算为 `εt,g`。
- **路径式预算上限（Pathwise Cap）**：每个属性有预承诺总预算 `Ba` 和已累计开销 `La`；仅当所有受影响属性满足 `La + εt,g ≤ Ba` 时才准入私有选择，否则返回固定通用视图、零额外成本、账本不变。
- **接口契约（Interface Contract）**：包含六项不变量——(C1) 视图词汇表跨相邻存储共享；(C2) 全集计费；(C3) 每个发布视图要么邻接不变要么由EM采样、且原始记忆与内部分数不外泄；(C4) 自适应执行仅依赖公共输入与已发布历史；(C5) 每次执行路径上都执行前瞻性上限检查、通用回退和账本更新；(C6) 下游响应LLM及可观察控制信号在给定公共输入和历史条件下与原始记忆独立。
- **理论保证**：在接口契约满足下，定理1证明整个增强转录 `τ̃T`（含查询、视图、控制信号、响应）对每个受保护属性满足纯 `Ba`-DP；普通转录 `τT` 作为后处理继承该保证。推论1将保证扩展到跨多个受保护组不同的存储，最小覆盖代价 `κ(M, M′)` 决定组合隐私损失。附录B.4给出后验赔率解释：观察转录事件最多将先验赔率改变 `e^Ba` 倍，且与先验无关。
- **失败模式分析**：附录B.5逐一构造反例，说明缺乏公共视图支持、计费遗漏、确定性选择、原始记忆依赖的信号、无限重复有效EM发布各自都会破坏 `Ba`-DP。

## 3. 实验设计

**数据与基准（Benchmark）**：

## 6. 主要结论与发现

- **隐私有效性**：两种DP-MemView模式在所有模型和轨道上将转录可区分性保持在接近随机水平（如PairedMem上AUC 0.464–0.562），而RawReadSet（0.730–0.942）、TaskMin（0.630–0.963）、OutputFilter（0.647–0.885）均保持高度可区分。GenericOnly和TypedMask虽然也达到机会水平区分度，但以牺牲个性化效用为代价。
- **效用保持**：DP-MemView在整体响应质量`U`上优于RawReadSet、TaskMin、OutputFilter，且相较于GenericOnly和TypedMask恢复了更多目标必需个性化。预分配模式在`tRec`上达到最高（如Qwen+PairedMem下0.559 vs RawReadSet 0.521），在线模式的`Unsup`更低（0.119 vs RawReadSet 0.136），两种模式分别适合已知计划收费数和未知未来收费数的场景。
- **预算行为**：`Ba`控制局部EM参数大小（`Ba=8`时AUC升至0.608），`K`决定每个预算支持的等额收费次数（K增大同时提升`tRec`和`Unsup`）。
- **接口契约必要性**：移除C2导致重建DP界从2.0翻倍为4.0（AUC升至0.554）；移除C3导致无有限纯DP界（AUC升至0.754）；移除C5导致累计收费达5.33（AUC升至0.599）。这些变体虽提升`tRec`，但以破坏`Ba`-DP保证为代价。
- **理论贡献**：完整自适应转录满足逐属性纯`Ba`-DP；复合存储差异的隐私代价为最小覆盖集合的总预算；观察转录事件对攻击者先验赔率的影响被限定在`e^Ba`因子内。

## 7. 优点

- **问题形式化清晰**：将长期记忆隐私精确定义为自适应转录隐私问题，区分了增强转录（含视图）与普通转录（仅应用可见），并明确后处理继承性。
- **架构与证明的严谨性**：接口契约六项不变量（C1–C6）分解了隐私保证的必要条件，定理1的证明按三个案件（邻接不变、未计费属性、计费属性）逐一处理视图分布，逻辑严整；推论1通过链式中间存储扩展多组差异；附录B.5提供隔离反例，论证每个保障的必要性。
- **属性级计费优于文档级或值级保护**：允许组间重叠、允许多属性共同蕴含一个事实，更贴近真实隐私语义；完整计费加前瞻性上限保证了路径上累计损失恒≤Ba。
- **实用导向的接口设计**：视图词汇公开共享、评分函数可替换、与具体LLM无关；在线和预分配两种模式适应不同预算管理场景；通用回退提供优雅降级。
- **实验设计兼顾内外部效度**：合成配对数据提供精确反事实控制，公共语料迁移轨道验证超越模板的泛化性；盲评、冻结审计器、固定查询轨迹等方法保证了比较的客观公平。

## 8. 不足与局限

- **评估依赖合成与固定协议**：转移轨道仍复用PairedMem的骨架、查询和策略，并非完全自然的开放域对话；公共语料文本是人工筛选和编辑的，可能丢失真实交互的噪声和多样性。
- **未覆盖内容相关检索**：论文明确说明`ReadPolicy`不依赖记忆内容，内容相关检索（如语义相似检索）不在定理保证范围内；需使其邻接不变或另外私有计费，这会显著增加实现复杂性。
- **单槽激活限制**：每轮仅激活一个槽位，未端到端测试多槽并发时的槽位顺序依赖（C4子情况），论文承认该局限并在契约层面覆盖。
- **一维属性组假设**：属性分组`{Ia}`需由策略完整指定，若遗漏可能隐含某属性的位置，则该位置变化落在保证之外；完整分组在实践中可能难以逐一验证。
- **LLM响应模型假设较强**：式(2)假设响应LLM是固定、存储无关的条件通道；若LLM具备记忆能力或提示注入可改变该假设，则保证不成立。
- **隐私审计范围有限**：嵌入分类器审计器仅代表一类攻击策略；T=16的短轨迹是否足以探测长期累积泄露（如Ba=8时的AUC上升所暗示的）需要更长交互的验证。
- **算力报告不足**：未提供GPU数量、运行时长、总能耗等，降低了结果的可复现性细节支撑。
- **实用部署挑战**：预算耗尽后所有相关槽位将退化为通用视图，长期使用后个性化能力会显著衰减；预分配模式需要事先知道计划的计费次数，在开放对话中难以精确预估。
